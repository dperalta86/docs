---
title: "Annotations"
description: "Backend hint markers on schema fields"
---

An annotation is a marker placed at the end of a field. It records how you expect the field to be used.

```chameleon
entity User {
    id: uuid primary,
    email: string,

    session_token: string @cache,
    monthly_spent: decimal @olap,
    embedding: vector(384) @vector,
}
```

<Warning>
  Annotations have **no effect today**. They are parsed, checked and stored with the schema, but the generated SQL is the same with or without them, and no query or mutation uses them. Every field lives in PostgreSQL. There is no routing to other stores.
</Warning>

## Available annotations

| Annotation | Meaning | Type requirement |
|------------|---------|------------------|
| `@cache` | Short-lived or frequently read data | None |
| `@olap` | Analytical or aggregated data | None |
| `@vector` | Embedding for similarity search | Must be `vector(N)` |
| `@ml` | Machine-learning related data | None |

```chameleon
entity Product {
    id: uuid primary,
    name: string,
    views_today: int @cache,
    monthly_sales: decimal @olap,
    embedding: vector(384) @vector,
    score: float @ml,
}
```

The meaning is documentation for readers of the schema. Nothing in ChameleonDB currently acts on it.

## Syntax

The annotation goes after the type and modifiers:

```chameleon
entity Example {
    id: uuid primary,
    a: string @cache,
    b: int nullable @cache,
    c: vector(8) @vector,
}
```

Only one annotation per field is accepted; a second is a parse error:

```text
d: string @cache @olap,
```

```text
Parse error at line 3, column 22: Unexpected token: Token(13, "@olap"), expected one of: ","
```

## Rules checked by `validate`

| Rule | Error |
|------|-------|
| `@vector` only on `vector(N)` | `Field 'e' in 'U' uses @vector but type is 'String', expected vector(N)` |
| No annotation on a `primary` field | `Field 'id' in 'U' is primary and cannot have @cache annotation` |
| No annotation on a `unique` field | `Field 'e' in 'U' is unique and cannot have @cache annotation` |

Anything else after the `@` is a parse error.

## Effect on the schema

- The annotation is part of the schema text, so adding or removing one changes the schema hash and `migrate` registers a new version in the vault.
- It does not change the generated `CREATE TABLE`, so existing tables are unaffected.

## pgvector

`@vector` does not install anything. A `vector(N)` column needs the pgvector extension, which you must enable yourself (`CREATE EXTENSION vector;`) before running `migrate`. See [Field Types](/schema/fields-types#vectorn).

## Best practices

<Tip>
  **Treat annotations as comments with a checked syntax.** Add them where the intent is clear to the next reader.
</Tip>

<Tip>
  **Do not rely on them for behavior.** If you need caching or a separate analytics store, build it in your application.
</Tip>
