Every field has an explicit type. ChameleonDB does not infer types.

## Basic syntax

```text
fieldName: type modifiers @annotation,
```

```chameleon
entity Example {
    id: uuid primary,
    email: string unique,
    age: int nullable,
    created_at: timestamp default now(),
}
```

## Type reference

These are the types the generator emits. The mapping comes from the migration generator, so the table below is what `CREATE TABLE` will contain.

| Type | PostgreSQL column | Notes |
|------|-------------------|-------|
| `uuid` | `UUID` | |
| `string` | `VARCHAR` | No length limit |
| `int` | `INTEGER` | **32-bit**, -2,147,483,648 to 2,147,483,647 |
| `decimal` | `NUMERIC` | No precision or scale |
| `bool` | `BOOLEAN` | |
| `timestamp` | `TIMESTAMP` | **Without** time zone |
| `float` | `DOUBLE PRECISION` | |
| `vector(N)` | `VECTOR(N)` | Needs the pgvector extension |
| `[type]` | `type[]` | PostgreSQL array |

<Warning>
  `int` is a 32-bit `INTEGER`, not `BIGINT`, and `timestamp` is `TIMESTAMP`, not `TIMESTAMPTZ`. A Go `int64` outside the 32-bit range is rejected by PostgreSQL, and time zone information is not stored; keep timestamps in a single zone, preferably UTC.
</Warning>

## Scalar types

### uuid

```chameleon
entity Example {
    id: uuid primary,
    owner_id: uuid,
}
```

Commonly used for primary keys. Use `default uuid()` to let PostgreSQL generate it (`gen_random_uuid()`).

### string

```chameleon
entity Example {
    id: uuid primary,
    email: string unique,
    bio: string nullable,
}
```

### int

```chameleon
entity Example {
    id: uuid primary,
    quantity: int,
    views: int nullable,
}
```

### decimal

```chameleon
entity Example {
    id: uuid primary,
    price: decimal,
}
```

`NUMERIC` without a declared precision keeps exact values, which makes it the right choice for money.

### float

```chameleon
entity Example {
    id: uuid primary,
    rating: float,
}
```

<Warning>
  Use `decimal`, not `float`, for currency. Floating-point values are approximate.
</Warning>

### bool

```chameleon
entity Example {
    id: uuid primary,
    active: bool,
}
```

### timestamp

```chameleon
entity Example {
    id: uuid primary,
    created_at: timestamp default now(),
    deleted_at: timestamp nullable,
}
```

## Special types

### vector(N)

```chameleon
entity Product {
    id: uuid primary,
    embedding: vector(384) @vector,
}
```

- The dimension is a number written in parentheses. The type checker does not validate it beyond parsing; PostgreSQL and pgvector enforce their own limits when the table is created.
- ChameleonDB does **not** run `CREATE EXTENSION vector`. Install and enable pgvector in your database before migrating.
- The query builder has no vector similarity operators.
- `vector(N)` columns cannot have a default value.

`@vector` is optional: it is an [annotation](/schema/annotations), and the column type does not depend on it.

## Collection types

```chameleon
entity Article {
    id: uuid primary,
    tags: [string],
    scores: [int],
}
```

An array field becomes `type[]` (`VARCHAR[]`, `INTEGER[]`). The parser also accepts nested arrays and arrays of vectors (`[[int]]`, `[vector(3)]`), which generate `INTEGER[][]` and `VECTOR(3)[]`, but these forms are not covered by tests; prefer the simple one-level arrays.

Arrays cannot have a default value.

## Default values

A default is written after the type: `default <value>`. The type checker accepts only these combinations:

| Type | Allowed default | SQL |
|------|-----------------|-----|
| `uuid` | `uuid()` or `uuid_v4()` | `gen_random_uuid()` |
| `string` | `"text"` | `'text'` |
| `int` | `5`, `-5` | `5`, `-5` |
| `decimal` | `0`, `1.5`, `-1.5` | `0`, `1.5`, `-1.5` |
| `float` | `1`, `1.5` | `1`, `1.5` |
| `bool` | `true`, `false` | `true`, `false` |
| `timestamp` | `now()` | `NOW()` |

A value wrapped in parentheses, such as `default (5)`, is also accepted.

```chameleon
entity Account {
    id: uuid primary default uuid(),
    role: string default "user",
    active: bool default true,
    balance: decimal default 0,
    created_at: timestamp default now(),
}
```

Mismatches are reported by `validate`:

```
Field 'r' in 'U' has invalid default 'IntLiteral(5)' for type 'String'
Field 'r' in 'U' uses unsupported default function 'now()' for type 'String'
```

<Note>
  `gen_random_uuid()` is built into PostgreSQL 13 and later. On older versions you need the `pgcrypto` extension.
</Note>

## Complete example

```chameleon
entity Product {
    id: uuid primary default uuid(),
    sku: string unique,

    name: string,
    description: string nullable,

    price: decimal,
    discount: decimal nullable,

    stock: int default 0,
    active: bool default true,

    created_at: timestamp default now(),
    updated_at: timestamp nullable,

    tags: [string],

    views_today: int @cache,
    monthly_sales: decimal @olap,
    embedding: vector(384) @vector,
}
```

## What `validate` checks

- The type is one of the names above (a typo is a parse error)
- Defaults match the type
- `@vector` is used on a `vector(N)` field

It does **not** check vector dimensions, nested array types or value ranges.

## Best practices

<Tip>
  **Use `uuid` for primary keys**, with `default uuid()`.
</Tip>

<Tip>
  **Use `decimal` for money.**
</Tip>

<Tip>
  **Use `nullable` only for genuinely optional data.** Fields are `NOT NULL` by default.
</Tip>
