## Order by

```go
result, err := eng.Query("User").
    Select("id", "name", "created_at").
    OrderBy("created_at", "desc").
    Execute(ctx)
```

```sql
SELECT "id", "name", "created_at"
FROM "users"
ORDER BY "created_at" DESC
```

The direction is `"asc"` or `"desc"`, in lowercase. Any other value, including `"DESC"`, is treated as ascending.

<Warning>
  Because `"DESC"` silently becomes ascending, always pass lowercase `"desc"`.
</Warning>

You can only order by fields of the main entity, and each field must exist.

## Several order clauses

```go
eng.Query("User").
    OrderBy("name", "asc").
    OrderBy("created_at", "desc").
    Execute(ctx)
```

```sql
ORDER BY "name" ASC, "created_at" DESC
```

The first call is the primary sort.

## Limit and offset

```go
eng.Query("User").
    Select("id", "name").
    OrderBy("created_at", "desc").
    OrderBy("id", "asc").
    Limit(10).
    Offset(20).
    Execute(ctx)
```

```sql
ORDER BY "created_at" DESC, "id" ASC
LIMIT 10
OFFSET 20
```

`Limit` and `Offset` take unsigned integers.

<Warning>
  Always use `OrderBy` with `Limit` and `Offset`, and end the order with a unique field such as `id`. Without a total order, PostgreSQL may return rows in any order and pages can overlap or skip rows. ChameleonDB does not warn if you forget.
</Warning>

### Pagination helper

```go
func ListUsers(ctx context.Context, eng *engine.Engine, page, pageSize uint64) ([]engine.Row, error) {
    result, err := eng.Query("User").
        Select("id", "name", "created_at").
        OrderBy("created_at", "desc").
        OrderBy("id", "asc").
        Limit(pageSize).
        Offset((page - 1) * pageSize).
        Execute(ctx)
    if err != nil {
        return nil, err
    }
    return result.Rows, nil
}
```

This is offset pagination. For large tables, deep offsets get slower; there is no cursor (keyset) helper, but you can build one with `Filter` on the sort fields.

## Select

```go
eng.Query("User").Select("id", "name", "email").Execute(ctx)
```

```sql
SELECT "id", "name", "email"
FROM "users"
```

Fetching only the fields you need reduces transfer and memory. If you also use `Include()`, keep `"id"` in the list.

## Debug

```go
eng.Query("User").
    Select("id", "name").
    Filter("email", "like", "ana").
    Debug().
    Execute(ctx)
```

```
[SQL]
SELECT "id", "name"
FROM "users"
WHERE "email" LIKE $1 ESCAPE '\'

[PARAMS]
$1 = String("%ana%")
```

`.DebugTrace()` also prints the duration and row count. See [Debug Mode](/guides/debugging).

## Combining features

```go
result, err := eng.Query("User").
    Select("id", "name", "created_at").
    Filter("age", "gte", 18).
    Filter("orders.total", "gt", 50).
    Include("orders.items").
    OrderBy("created_at", "desc").
    Limit(10).
    Execute(ctx)
```

```sql
-- 1. main query
SELECT DISTINCT "users"."id", "users"."name", "users"."created_at"
FROM "users"
INNER JOIN "orders" ON "orders"."user_id" = "users"."id"
WHERE "users"."age" >= $1 AND "orders"."total" > $2
ORDER BY "users"."created_at" DESC
LIMIT 10

-- 2. orders of the matched users
SELECT ... FROM "orders" WHERE "user_id" = ANY($1)

-- 3. items of those orders
SELECT ... FROM "order_items" WHERE "order_id" = ANY($1)
```

What it does:

1. Finds users aged 18 or more
2. That have at least one order with total over 50
3. Loads **all** their orders, not only the ones over 50, and the items of those orders
4. Sorts the users by newest first and returns the first 10

Note that `Limit` applies to users, not to orders or items.

## What is validated

The entity, every field (in `Select`, `Filter` paths and `OrderBy`), every relation (in `Include` and relation filters) and the operator are checked before SQL is generated.

| Not checked | Result |
|-------------|--------|
| Type of the filter value | PostgreSQL rejects it |
| `Limit` without `OrderBy` | Runs; order is not guaranteed |
| Sorting by a field missing from a `DISTINCT` select list | PostgreSQL error |

## Performance tips

<AccordionGroup>
  <Accordion title="Select only what you need">
    ```go
    eng.Query("User").Select("id", "name", "email").Execute(ctx)
    ```
  </Accordion>

  <Accordion title="Include only the relations you read">
    Each included relation, and each nested level, is one more query.
  </Accordion>

  <Accordion title="Index your foreign keys and sort fields">
    Eager queries filter on the foreign key (`user_id = ANY(...)`) and relation filters join on it. ChameleonDB does not create indexes for you:

    ```sql
    CREATE INDEX idx_orders_user_id ON orders(user_id);
    ```
  </Accordion>

  <Accordion title="Paginate with a stable order">
    ```go
    OrderBy("created_at", "desc").OrderBy("id", "asc").Limit(20).Offset(40)
    ```
  </Accordion>

  <Accordion title="Look at the SQL">
    Use `.Debug()` and PostgreSQL's `EXPLAIN ANALYZE`.
  </Accordion>
</AccordionGroup>

## Limitations

Not supported today:

- Aggregations (`count`, `sum`, `avg`) and group by
- Subqueries
- `OR` conditions
- The `in` operator and `IS NULL` filters
- Transactions
- Joins in the main query other than the one used for relation filters
