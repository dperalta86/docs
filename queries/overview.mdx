Queries are built with a **chainable API**. Every query targets an entity from your schema, and its entity, fields, relations and operators are checked against that schema before SQL is generated. Values are sent to PostgreSQL as bound parameters, never written into the SQL text.

## Basic structure

```go
result, err := eng.Query("EntityName").
    Select("id", "name").
    Filter("field", "operator", value).
    Include("relation").
    OrderBy("field", "asc").
    Limit(10).
    Offset(0).
    Execute(ctx)
```

`eng` comes from `engine.NewEngine()` and a connected pool. See the [Query Builder](/query-builder) page for setup.

## Example schema

The examples in this section use:

```chameleon
entity User {
    id: uuid primary default uuid(),
    email: string unique,
    name: string,
    age: int nullable,
    status: string default "active",
    created_at: timestamp default now(),
    orders: [Order] via user_id,
}

entity Order {
    id: uuid primary default uuid(),
    total: decimal,
    status: string,
    created_at: timestamp default now(),
    user_id: uuid,
    user: User,
    items: [OrderItem] via order_id,
}

entity OrderItem {
    id: uuid primary default uuid(),
    quantity: int,
    price: decimal,
    order_id: uuid,
    order: Order,
}
```

## Fetch all records

```go
result, err := eng.Query("User").Execute(ctx)

for _, row := range result.Rows {
    fmt.Println(row["name"])
}
```

`result.Rows` is a slice of `map[string]interface{}`. Without `Select()`, the query lists every field of the entity; the order of the columns in the SQL is not guaranteed, so read values by name.

## Field projection

```go
result, err := eng.Query("User").
    Select("id", "name", "email").
    Execute(ctx)
```

```sql
SELECT "id", "name", "email"
FROM "users"
```

Fetching fewer columns reduces transfer and memory.

<Note>
  If you use `Include()`, keep `"id"` in `Select()`. The ids of the main rows are what the eager queries use to find related rows; without them, nothing is loaded.
</Note>

## What is checked

Before SQL is generated:

| Check | Example that fails |
|-------|--------------------|
| Entity exists | `eng.Query("Products")` when only `Product` exists |
| Fields in `Select`, `Filter` and `OrderBy` exist | `.Filter("phone", ...)` when `phone` is not a field |
| Relations in `Include` and relation filters exist | `.Include("address")` when `address` is not a relation |
| Filter paths are `field` or `relation.field` | `.Filter("orders.items.price", ...)` |
| Operator is supported | `.Filter("age", "in", ...)` |

<Warning>
  The query builder does **not** check value types. `Filter("age", "eq", "not a number")` generates valid SQL and fails when PostgreSQL rejects it. There is also no warning for `Limit()` without `OrderBy()`. Validate inputs in your application.
</Warning>

## Limits

- Filters combine with `AND` only; the Go builder has no `OR`
- Relation filters and `Include` work with has-many relations (the ones declared with `via`)
- No aggregations, group by, subqueries or transactions
- `in` is not supported

## Debug mode

```go
eng.Query("User").
    Select("id", "name").
    Filter("email", "like", "ana").
    Debug().
    Execute(ctx)
```

```
[SQL]
SELECT "id", "name"
FROM "users"
WHERE "email" LIKE $1 ESCAPE '\'

[PARAMS]
$1 = String("%ana%")
```

See [Debug Mode](/guides/debugging) for traces and for inspecting eager queries.
