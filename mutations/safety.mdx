## Overview

Insert, update and delete operations are validated before any SQL is sent. Some checks run in Go, others are left to PostgreSQL. This page lists what each layer checks, so you know what the library guarantees and what it does not.

## WHERE clause requirement

**Updates and deletes without a filter are blocked.** The check runs before SQL is generated.

```go
// Fails: no Filter()
_, err := eng.Update("User").
    Set("role", "admin").
    Execute(ctx)
// SafetyError: UPDATE requires a WHERE clause

_, err = eng.Delete("User").Execute(ctx)
// SafetyError: DELETE without WHERE is blocked
```

```go
// Works: explicit filter
eng.Update("User").
    Filter("id", "eq", userID).
    Set("role", "admin").
    Execute(ctx)
```

<Warning>
  The error message suggests `ForceUpdateAll()` and `ForceDeleteAll()`. **These methods do not exist** in the current API, so there is currently no way to run an unfiltered update or delete through ChameleonDB. This is a known documentation bug in the message itself. If you need a full-table operation, run SQL directly against PostgreSQL.
</Warning>

Filters are combined with `AND`. Filtering on a field that is not in the entity returns an `UnknownFieldError` before reaching the database.

<Note>
  A filter does not make an update safe by itself. `Filter("status", "neq", "x")` can still match every row. Check `result.Affected` and test with `.Debug()`.
</Note>

## What is validated, and where

### In Go (before the database)

| Check | Applies to | Error |
|-------|-----------|-------|
| Entity exists | all | `UnknownEntityError` |
| Field exists | insert, update, filters | `UnknownFieldError` |
| `uuid` fields hold a valid UUID string | insert, update | `FieldFormatError` |
| `string` fields hold a Go `string` | insert, update | `TypeMismatchError` |
| Fields whose name contains `email` look like an email | insert | `FieldFormatError` |
| Non-nullable fields are not `nil` | insert, update | `NotNullError` |
| Required fields are present (not nullable, no default, not primary key) | insert | `NotNullError` |
| Primary key is not updated | update | `ConstraintError` |
| At least one `Set()` | update | `SafetyError` |
| At least one `Filter()` | update, delete | `SafetyError` |
| Filter operator is supported | update, delete | `unsupported filter operator` |

<Warning>
  The Go checks cover `uuid` and `string` types only. Other types (`int`, `decimal`, `bool`, `timestamp`, ...) are not validated in Go; a wrong value reaches PostgreSQL, which rejects it with its own error.
</Warning>

<Note>
  The email check is by field **name**: any field whose name contains `email` (case-insensitive) must match a basic `a@b.c` pattern. This is a convention of the validator, not something declared in the schema.
</Note>

### In PostgreSQL

Integrity rules are left to the database, and the error is mapped to a typed error:

| Rule | Error |
|------|-------|
| `UNIQUE` | `UniqueConstraintError` |
| Foreign key (parent missing on insert/update, or children exist on delete) | `ForeignKeyError` |
| `NOT NULL` | `NotNullError` |
| `CHECK` | `ConstraintError` |

Other PostgreSQL errors are returned wrapped, without a typed mapping.

## Filter operators

Mutation filters accept:

| Operator | SQL |
|----------|-----|
| `eq` | `=` |
| `neq`, `ne` | `!=` |
| `gt`, `gte`, `lt`, `lte` | `>`, `>=`, `<`, `<=` |
| `like`, `ilike` | `LIKE`, `ILIKE` |

Details that matter:

- Values are bound as parameters (`$1`, `$2`, ...), never written into the SQL text. Table and column names are validated against the schema and quoted.
- In mutations, `like` and `ilike` use **the pattern you pass**, so you add `%` yourself. This differs from the query builder, where `like` means "contains" and wildcards are escaped.
- There is no `IS NULL` filter: `Filter("deleted_at", "eq", nil)` becomes `deleted_at = NULL`, which never matches in SQL.
- A filter is keyed by field and operator. Calling `Filter("age", "gt", 18)` twice keeps only the last value; two different operators on the same field are both kept.
- Filtering by a Go `time.Time` is not supported yet; pass a string.

## Typed errors

```go
import "errors"

_, err := eng.Insert("User").
    Set("email", "ana@mail.com").
    Set("name", "Ana").
    Execute(ctx)

var uniqueErr *engine.UniqueConstraintError
var fkErr *engine.ForeignKeyError
var notNullErr *engine.NotNullError
var safetyErr *engine.SafetyError

switch {
case errors.As(err, &uniqueErr):
    // duplicate value in a unique field
case errors.As(err, &fkErr):
    // referenced parent does not exist
case errors.As(err, &notNullErr):
    // missing or null required field
case errors.As(err, &safetyErr):
    // missing WHERE or SET
case err != nil:
    return fmt.Errorf("operation failed: %w", err)
}
```

Other error types: `TypeMismatchError`, `FieldFormatError`, `UnknownEntityError`, `UnknownFieldError`, `ConstraintError`. (`ForeignKeyConstraintError` is defined but the database error mapper does not produce it today; foreign key violations arrive as `ForeignKeyError`, on delete too.) Mutation errors implement a `Code()` method (for example `UNIQUE_CONSTRAINT_VIOLATION`, `SAFETY_VIOLATION`) and `engine.IsMutationError(err)`.

### Suggested HTTP mapping

This is a suggestion for web apps, not behavior of the library:

| Error | Status |
|-------|--------|
| `SafetyError`, `NotNullError`, `FieldFormatError`, `TypeMismatchError`, unknown entity or field | 400 |
| `ForeignKeyError` | 400 or 422 |
| `UniqueConstraintError` | 409 |
| `ForeignKeyError` on delete (children exist) | 409 |

## Practical habits

1. **Validate input in your application** (formats, lengths) before calling the engine. The built-in checks are intentionally narrow.
2. **Check `Affected`**. A filter that matches nothing is not an error.
3. **Use `.Debug()` while developing.** It prints the SQL and the values, so do not enable it where logs contain sensitive data.
4. **Take backups** before bulk updates or deletes.
5. **Wrap multi-step changes carefully.** ChameleonDB does not expose transactions yet, so each mutation is its own statement.

## Pre-flight checklist

- The engine was created with `engine.NewEngine()` and connected with `eng.Connect(ctx, cfg)`
- The mutation package is imported: `_ "github.com/chameleon-db/chameleondb/chameleon/pkg/engine/mutation"`
- Updates and deletes have the filter you intend, and you know the expected affected count
- You tested the statement with `.Debug()` against a non-production database
- Errors are handled by type
