## Overview

`Update` builds an `UPDATE ... SET ... WHERE ... RETURNING *` statement. **A filter is required**: an update with no `Filter()` is rejected before any SQL is generated.

<Warning>
  Without a filter you get a `SafetyError`:

  ```go
  _, err := eng.Update("User").
      Set("name", "John").
      Execute(ctx)
  // SafetyError: UPDATE requires a WHERE clause
  ```

  There is no way to run an unfiltered update through ChameleonDB. Add a `Filter()`.
</Warning>

## Basic update

```go
result, err := eng.Update("User").
    Filter("id", "eq", userID).
    Set("name", "Ana Martinez").
    Execute(ctx)
if err != nil {
    return err
}

fmt.Printf("updated %d rows\n", result.Affected)
```

## Several fields

```go
result, err := eng.Update("User").
    Filter("id", "eq", userID).
    Set("name", "Ana Martinez").
    Set("email", "ana.martinez@mail.com").
    Execute(ctx)
```

## Several filters

Filters are combined with `AND`:

```go
result, err := eng.Update("Post").
    Filter("author_id", "eq", authorID).
    Filter("published", "eq", false).
    Set("published", true).
    Execute(ctx)
```

Supported operators: `eq`, `neq` (or `ne`), `gt`, `gte`, `lt`, `lte`, `like`, `ilike`. Notes:

- `like` and `ilike` mean "contains", as in queries: `Filter("name", "like", "ana")` matches `%ana%`. `%`, `_` and `\` in the value match literally.
- `Filter("x", "eq", nil)` becomes `x IS NULL` and `Filter("x", "neq", nil)` becomes `x IS NOT NULL`. Any other operator with `nil` returns an error.
- Setting the same field and operator twice keeps only the last value.
- Pass dates as strings, for example `"2026-01-01"`. A Go `time.Time` is not supported in filters yet.

```go
result, err := eng.Update("Post").
    Filter("created_at", "lt", "2024-01-01").
    Set("archived", true).
    Execute(ctx)
```

## Result

```go
type UpdateResult struct {
    Records  []map[string]interface{} // updated rows (RETURNING *)
    Affected int                      // number of rows updated
}
```

```go
if result.Affected == 0 {
    return fmt.Errorf("no record matched")
}
```

## What is validated

- The entity, every field in `Set` and every field in `Filter` exist
- At least one `Set` and one `Filter`
- The **primary key cannot be updated** (`ConstraintError`)
- `uuid` fields hold a valid UUID string and `string` fields hold a Go `string`
- Non-nullable fields are not set to `nil`

Other types are not checked in Go; PostgreSQL validates them. Unique, foreign key and check constraints are enforced by PostgreSQL. See [Safety Guards](/mutations/safety).

## Error handling

```go
import "errors"

result, err := eng.Update("User").
    Filter("id", "eq", userID).
    Set("email", "ana@mail.com").
    Execute(ctx)

if err != nil {
    var uniqueErr *engine.UniqueConstraintError
    if errors.As(err, &uniqueErr) {
        return fmt.Errorf("email already in use: %w", err)
    }

    var safetyErr *engine.SafetyError
    if errors.As(err, &safetyErr) {
        return fmt.Errorf("update needs a filter and a field: %w", err)
    }

    return fmt.Errorf("update failed: %w", err)
}
_ = result
```

## Patterns

### Partial updates

```go
func (r *UserRepository) UpdateProfile(ctx context.Context, id string, name, email *string) error {
    update := r.eng.Update("User").Filter("id", "eq", id)

    if name != nil {
        update = update.Set("name", *name)
    }
    if email != nil {
        update = update.Set("email", *email)
    }

    result, err := update.Execute(ctx)
    if err != nil {
        return err
    }
    if result.Affected == 0 {
        return fmt.Errorf("user not found")
    }
    return nil
}
```

If both are `nil`, the update has no `Set` and fails with a `SafetyError`.

### Check the count

```go
if result.Affected > 1 {
    log.Printf("warning: updated %d users, expected 1", result.Affected)
}
```

<Warning>
  ChameleonDB does not expose transactions yet. Several updates in a row are independent statements. If you need atomicity across statements, run them through your own `pgx` transaction.
</Warning>

## Best practices

- Filter by primary key whenever you mean to touch one record.
- Check `Affected` and treat 0 as "not found" where that matters.
- A filter does not guarantee a small match: `Filter("status", "neq", "x")` may match every row. Try it with `.Debug()` first.
- Validate formats in your application before calling the engine.
