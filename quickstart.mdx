# Quick Start Guide

Create a project, declare a schema, preview the SQL and register the first version in the vault.

## Prerequisites

- **PostgreSQL**, running. Integration tests run against PostgreSQL 16; other versions are not yet verified.
- **Go 1.25.6 or newer**, only if you use the Go library in your application.
- Terminal access (bash, zsh, or PowerShell).

## Installation

See the [Installation Guide](/installation) for Linux, macOS, Windows and building from source.

Quick install on Linux and macOS:

```bash
curl -sSL https://chameleondb.dev/install | sh
```

The install script does not yet verify checksums. If that matters to you, build from source.

Verify the installation:

```bash
chameleon version
```

## Your first project

<Steps>
  <Step title="Initialize the project">
    Create a directory and initialize ChameleonDB:

    ```bash
    mkdir my-app
    cd my-app
    chameleon init
    ```

    **What it creates:**
    - `.chameleon/` with local state, journal and backups (not meant for version control)
    - `.chameleon.yml` with the project configuration
    - `schemas/example.cham`, an example schema
    - a `README.md` for the project

    The Schema Vault (`.chameleon/vault/`) is created by your first `chameleon migrate`, and starts in `readonly` mode.

    <Tip>
      Set a mode password with `chameleon config auth set-password`. It will be asked when you raise the integrity mode.
    </Tip>
  </Step>

  <Step title="Define your schema">
    Edit `schemas/example.cham` (or add more `.cham` files in `schemas/`):

    ```go schemas/example.cham
    entity User {
        id: uuid primary,
        email: string unique,
        name: string,
        created_at: timestamp default now(),
        posts: [Post] via author_id,
    }

    entity Post {
        id: uuid primary,
        title: string,
        content: string,
        published: bool default false,
        created_at: timestamp default now(),
        author_id: uuid,
        author: User,
    }
    ```

    Validate it:

    ```bash
    chameleon validate schemas/example.cham
    ```

    A valid schema ends with `✓ Schema is valid`. Errors include the line, a snippet and, when possible, a suggestion.
  </Step>

  <Step title="Configure the database connection">
    Set your PostgreSQL connection string:

    ```bash
    export DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
    ```

    <Note>
      Replace `user`, `password` and `mydb` with your own values. Do not commit real credentials.
    </Note>
  </Step>

  <Step title="Preview the migration">
    ```bash
    chameleon migrate --dry-run
    ```

    This prints the SQL without applying it. For the schema above, the script has this shape (the order of the columns inside each table can vary between runs):

    ```sql
    DROP TABLE IF EXISTS posts CASCADE;

    DROP TABLE IF EXISTS users CASCADE;

    CREATE TABLE users (
        id UUID PRIMARY KEY,
        name VARCHAR NOT NULL,
        email VARCHAR NOT NULL UNIQUE,
        created_at TIMESTAMP NOT NULL DEFAULT NOW()
    );

    CREATE TABLE posts (
        id UUID PRIMARY KEY,
        title VARCHAR NOT NULL,
        content VARCHAR NOT NULL,
        published BOOLEAN NOT NULL DEFAULT false,
        created_at TIMESTAMP NOT NULL DEFAULT NOW(),
        author_id UUID NOT NULL,
        FOREIGN KEY (author_id) REFERENCES users(id)
    );
    ```

    Read it before you apply it: the `DROP TABLE` statements remove existing tables and their data.
  </Step>

  <Step title="Raise the mode and apply">
    The first `chameleon migrate --apply` is not blocked. It creates the vault in `readonly` mode, so **later** migrations are blocked until you run `chameleon config auth set-password` and `chameleon config set mode=standard`.

    <Warning>
      `migrate --apply` drops and recreates every table in your schema. Point it at an empty or disposable database and read `--dry-run` first. See [`chameleon migrate`](/cli/migrate).
    </Warning>

    ```bash
    chameleon config auth set-password
    chameleon config set mode=standard
    chameleon migrate --apply
    ```

    `migrate --apply` verifies the vault, registers the schema as `v001` (with its SHA-256 hash), and then runs the SQL against your database.
  </Step>

  <Step title="Inspect the history">
    ```bash
    chameleon journal schema
    chameleon status
    chameleon verify
    ```
  </Step>
</Steps>

## Use the Go library

The Go library is a supporting component. It calls the Rust core through cgo, so the native library must be installed first. See [Using ChameleonDB as a Go SDK](/installation#using-chameleondb-as-a-go-sdk).

Run your program from the project directory. `NewEngine()` loads the schema from the vault and verifies its integrity.

```bash
go mod init my-app
go get github.com/chameleon-db/chameleondb/chameleon@latest
```

```go main.go
package main

import (
    "context"
    "fmt"
    "log"
    "os"

    "github.com/chameleon-db/chameleondb/chameleon/pkg/engine"
    "github.com/google/uuid"
)

func main() {
    ctx := context.Background()

    // Loads the schema from the vault and verifies its integrity.
    eng, err := engine.NewEngine()
    if err != nil {
        log.Fatal(err)
    }
    defer eng.Close()

    // Connect to PostgreSQL.
    config, err := engine.ParseConnectionString(os.Getenv("DATABASE_URL"))
    if err != nil {
        log.Fatal(err)
    }
    if err := eng.Connect(ctx, config); err != nil {
        log.Fatal(err)
    }

    // Insert a user.
    result, err := eng.Insert("User").
        Set("id", uuid.New().String()).
        Set("email", "ana@mail.com").
        Set("name", "Ana Garcia").
        Execute(ctx)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("User created: %v\n", result.ID)

    // Query users.
    users, err := eng.Query("User").
        Filter("email", "eq", "ana@mail.com").
        Execute(ctx)
    if err != nil {
        log.Fatal(err)
    }

    for _, user := range users.Rows {
        fmt.Printf("User: %s <%s>\n", user["name"], user["email"])
    }
}
```

```bash
go run main.go
```

## Query with relations

```go
// Query users with their posts (eager loading)
result, err := eng.Query("User").
    Select("id", "name", "email").
    Include("posts").
    Execute(ctx)
if err != nil {
    log.Fatal(err)
}

for _, user := range result.Rows {
    fmt.Printf("User: %s\n", user["name"])
}

if posts, ok := result.Relations["posts"]; ok {
    fmt.Printf("Loaded %d posts\n", len(posts))
}
```

<Note>
  `Include()` loads the related rows in a separate query per relation, instead of one query per parent row. The related rows are returned in `result.Relations`, keyed by relation name.
</Note>

## Debug mode

See the generated SQL and its parameters for a query:

```go
result, err := eng.Query("User").
    Select("id", "name", "email").
    Filter("email", "like", "ana").
    Debug().
    Execute(ctx)
```

The SQL text contains placeholders, and the values are listed separately:

```
[SQL]
SELECT "id", "name", "email"
FROM "users"
WHERE "email" LIKE $1 ESCAPE '\'

[PARAMS]
$1 = String("%ana%")
```

<Warning>
  Debug output prints parameter values. Do not enable it where logs can reach people who should not see that data.
</Warning>

## Integrity modes

Integrity modes control what the CLI allows. They do not replace database permissions.

```bash
# Check the current mode
chameleon config get mode

# Set a password for mode upgrades (recommended)
chameleon config auth set-password

# Upgrade to allow schema changes (asks for the password)
chameleon config set mode=standard

# Downgrade (no password required)
chameleon config set mode=readonly
```

<Warning>
  In `readonly` mode (the default), schema modifications are blocked. Raise the mode to `standard` for development.
</Warning>

## Common issues

<AccordionGroup>
  <Accordion title="vault not initialized">
    The vault is created by `chameleon migrate`. Run it in your project directory (use `--dry-run` first).

    ```bash
    chameleon migrate --dry-run
    ```
  </Accordion>

  <Accordion title="readonly mode: schema modifications are blocked">
    Raise the integrity mode.

    ```bash
    chameleon config auth set-password
    chameleon config set mode=standard
    ```
  </Accordion>

  <Accordion title="integrity violation">
    A vault file no longer matches its recorded hash. Check what changed and read the audit log.

    ```bash
    chameleon verify
    cat .chameleon/vault/integrity.log
    ```
  </Accordion>

  <Accordion title="DATABASE_URL not set">
    Set the environment variable.

    ```bash
    export DATABASE_URL="postgresql://user:pass@host:5432/db"
    ```
  </Accordion>
</AccordionGroup>
