description: 'Generate a ChameleonDB schema from an existing PostgreSQL database'

## Synopsis

```bash
chameleon introspect <database-url> [flags]
```

Read the tables of an existing PostgreSQL database and write a starting `.cham` schema.

## Description

`introspect` connects to the database, lists its tables and columns and writes a schema file. Treat the result as a **first draft** that you review and edit by hand: it captures tables, columns, primary keys and unique constraints, and little else (see [Limitations](#limitations)).

It only reads from the database. It writes one file, under `schemas/`.

Only PostgreSQL is supported.

## Arguments

<ParamField path="database-url" type="string" required>
  Connection string, or a reference to an environment variable.

  - Direct URL: `postgresql://user:pass@localhost/db`
  - `$DATABASE_URL`
  - `${DATABASE_URL}`
  - `env:DATABASE_URL`

  If the variable is unset or empty the command fails with `environment variable DATABASE_URL is not set or empty`.
</ParamField>

## Flags

<ParamField path="-o, --output" type="string" default="schema.cham">
  Output file name. A `.cham` extension is added if missing, and the file is placed under `schemas/`.

  ```bash
  chameleon introspect "$DATABASE_URL" -o blog.cham   # -> schemas/blog.cham
  ```
</ParamField>

<ParamField path="-f, --force" type="boolean" default="false">
  Overwrite an existing file without asking. No backup is made.
</ParamField>

## Example

```bash
chameleon introspect "postgresql://user:password@localhost/mydb"
```

```
ℹ Introspecting database...
✓ Database detected
ℹ Scanning tables...
✓ Found 2 table(s)
ℹ Generating schema...
✓ Schema written to schemas/schema.cham

ℹ Next steps:
  1. Review schema and adjust relations manually
  2. Run: chameleon validate
  3. Use with your application
```

Given:

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(255),
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE posts (
    id UUID PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    content TEXT,
    author_id UUID REFERENCES users(id),
    published BOOLEAN DEFAULT FALSE
);
```

the generated file contains one entity per table (`users` becomes `User`, `user_posts` becomes `UserPost`), with the mapped field types. Foreign keys are noted as comments for you to review, not turned into relations.

<Note>
  `chameleon validate` with no argument looks for `schema.cham` in the current directory. For a file under `schemas/`, pass the path: `chameleon validate schemas/schema.cham`.
</Note>

## Add relations by hand

```chameleon
entity User {
    id: uuid primary,
    email: string unique,
    name: string,
    posts: [Post] via author_id,
}

entity Post {
    id: uuid primary,
    title: string,
    author_id: uuid,
    author: User,
}
```

## Integrity mode

If a Schema Vault exists and the mode is `readonly` (the default), `introspect` is blocked:

```
✗ Read Only Paranoid Mode is active - introspection is blocked

ℹ Mode upgrade available:
   1. Run: chameleon config auth set-password
   2. Run: chameleon config set mode=standard
   3. Retry: chameleon introspect <database-url>

Error: readonly mode: introspect is blocked
```

If no vault exists yet (a new project, before the first `migrate`), the check is skipped with a warning. See [`chameleon config`](/cli/config).

## Overwrite protection

If the output file exists, you are asked what to do:

- **Default schema from `chameleon init`** - `Overwrite? (yes/no)`
- **A schema with your own entities** - choose `1` backup and overwrite (writes `<file>.backup`), `2` use another file name, or `3` cancel

`--force` skips these prompts.

## Type mapping

| PostgreSQL | ChameleonDB |
|------------|-------------|
| `uuid` | `uuid` |
| `text`, `varchar`, `character varying` | `string` |
| `integer`, `bigint`, `smallint` | `int` |
| `numeric`, `decimal` | `decimal` |
| `real`, `double precision` | `float` |
| `boolean` | `bool` |
| `timestamp`, `timestamp with time zone`, `date` | `timestamp` |
| anything else (`json`, `jsonb`, arrays, enums, ...) | `string` |

<Warning>
  Unmapped types silently become `string`, and `date` becomes `timestamp`. Review every field that is not a plain scalar.
</Warning>

## Limitations

- **Relations** - Foreign keys are left as comments; you write the relations
- **Defaults** - Not copied (for example `DEFAULT NOW()` is not reproduced)
- **Indexes, views, triggers, other constraints** - Not captured; only primary keys and unique columns
- **Schemas** - Intended for tables in the default schema

## Errors

```
failed to detect database: ...        # unreachable, bad URL, or not PostgreSQL
introspection failed: ...             # permission or query error
output path is a directory: ...
database-url cannot be empty
```

Make sure the database user can read the catalog and the tables. A `mysql://` or `sqlite://` URL is not supported.
