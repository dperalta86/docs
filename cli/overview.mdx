The ChameleonDB CLI manages `.cham` schemas, migrations for PostgreSQL, the local Schema Vault and its integrity modes.

## Installation

See the [Installation Guide](/installation). In short:

```bash
# Linux and macOS
curl -sSL https://chameleondb.dev/install | sh
```

On Windows, download the archive from the [releases page](https://github.com/chameleon-db/chameleondb/releases). It contains `chameleon.exe` and `chameleon.dll`, which must stay in the same directory and be reachable from your `PATH`.

### Verify the installation

```bash
chameleon version
```

<Note>
  The version is a subcommand (`chameleon version`). There is no `--version` flag.
</Note>

## Environment variables

<ParamField path="DATABASE_URL" type="string">
  PostgreSQL connection string. The default `.chameleon.yml` reads it as `${DATABASE_URL}`; `migrate` uses it to connect.

  ```bash
  export DATABASE_URL="postgresql://user:password@localhost:5432/dbname"
  ```
</ParamField>

<ParamField path="CHAMELEON_MODE_PASSWORD" type="string">
  Mode password for non-interactive use (for example in CI). It is used by `config set mode=...` and `config auth set-password`. Treat it like any other secret.
</ParamField>

<ParamField path="USER" type="string">
  Recorded as the author of each schema version registered by `migrate`. Defaults to `unknown`.
</ParamField>

## Command categories

### Project

- [`chameleon init`](/cli/init) - Initialize a project
- `chameleon status` - see [`status`](/cli/status)

### Schema management

- [`chameleon migrate`](/cli/migrate) - Preview and apply migrations
- [`chameleon validate`](/cli/validate) - Validate one schema file
- [`chameleon introspect`](/cli/introspect) - Generate a schema from an existing PostgreSQL database
- `chameleon check [file]` - Check a schema file (intended for editor integrations)

### Integrity and audit

- [`chameleon verify`](/cli/verify) - Verify the Schema Vault against its recorded hashes
- [`chameleon status`](/cli/status) - Show schema, vault and mode
- [`chameleon journal`](/cli/journal) - Read the operation journal and the version history

### Configuration

- [`chameleon config`](/cli/config) - Read and set the integrity mode, the mode password and the schema paths

### Utilities

- `chameleon version` - Show the version
- `chameleon query [entity]` - Run queries from the terminal (for testing)
- `chameleon uninstall` - Remove ChameleonDB from your system
- `chameleon dashboard serve` and `chameleon playground-sql serve` - Local development servers

<Warning>
  The dashboard and playground servers are meant for local development. Do not expose them on a network.
</Warning>

## Project structure

After `chameleon init`:

```
.
├── .chameleon.yml          # Project configuration
├── .chameleon/             # Admin directory
│   ├── .gitignore          # Ignores state/, journal/ and backups/
│   ├── config.yml          # Source configuration
│   ├── state/              # Local state
│   ├── journal/            # Operation journal
│   └── backups/
├── schemas/                # Schema files
│   └── example.cham        # Example schema
└── README.md
```

The Schema Vault (`.chameleon/vault/`) is created by the first `chameleon migrate`.

## Common workflows

### First-time setup

```bash
# 1. Initialize the project
chameleon init my-project
cd my-project

# 2. Point to an empty or disposable database
export DATABASE_URL="postgresql://user:password@localhost:5432/dbname"

# 3. Edit the schema, then validate it
vim schemas/example.cham
chameleon validate schemas/example.cham

# 4. Preview the migration and read it
chameleon migrate --dry-run

# 5. Apply it
chameleon migrate --apply
```

### Checking state

```bash
chameleon status          # version, vault integrity and mode
chameleon verify          # detailed integrity check
chameleon journal schema  # version history
chameleon journal last    # recent operations
```

## Global flags

<ParamField path="-v, --verbose" type="boolean" default="false">
  Verbose output
</ParamField>

<ParamField path="--help" type="boolean">
  Show help for any command

  ```bash
  chameleon migrate --help
  ```
</ParamField>

## Exit codes

- `0` - Success
- Non-zero - The command failed (for example validation, integrity or connection errors)

## Getting help

```bash
chameleon --help
chameleon migrate --help
chameleon journal --help
```
