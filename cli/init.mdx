## Synopsis

```bash
chameleon init [name]
```

Create a new ChameleonDB project with schema files and configuration.

## Description

Initializes a ChameleonDB project by creating:

- `.chameleon.yml` - Main configuration file
- `.chameleon/` - Admin directory (config, state, journal, backups)
- `schemas/` - Directory for schema files
- `schemas/example.cham` - Example schema to get started
- `README.md` - Getting started guide

If a project name is provided, creates a new directory. Otherwise, initializes in the current directory.

## Arguments

<ParamField path="name" type="string" optional>
  Project name. Creates a new directory with this name.
  
  If omitted, initializes in the current directory.
</ParamField>

## Created Files

### .chameleon.yml

Main configuration file:

```yaml
database:
  driver: postgresql
  connection_string: ${DATABASE_URL}

schema:
  paths:
    - ./schemas
  merged_output: .chameleon/state/schema.merged.cham

features:
  auto_migration: true
  rollback: true
  backup_on_migrate: true
  audit_logging: true

safety:
  validation: true
  confirmation: false
```

### schemas/example.cham

Starter schema with blog example:

```chameleon
// ChameleonDB Example Schema
// This is a simple blog schema to get you started

entity User {
    id: uuid primary,
    email: string unique,
    name: string,
    created_at: timestamp default now(),
}

entity Post {
    id: uuid primary,
    title: string,
    content: string,
    published: bool,
    author_id: uuid,
    created_at: timestamp default now(),
}

entity Comment {
    id: uuid primary,
    content: string,
    post_id: uuid,
    user_id: uuid,
    created_at: timestamp default now(),
}
```

### .chameleon/ Structure

```
.chameleon/
├── .gitignore          # ignores state/, journal/ and backups/
├── config.yml          # Configuration source
├── state/              # State tracking
├── journal/            # Operation journal (daily rotation)
└── backups/
```

<Note>
  The Schema Vault (`.chameleon/vault/`) is created by the first `chameleon migrate`, not by `init`.
</Note>

## Behavior

### Already Initialized

If `.chameleon.yml` already exists:

```bash
chameleon init
```

**Error:**
```
❌ ChameleonDB already initialized in current directory
   Run 'chameleon migrate' to manage migrations or delete .chameleon.yml to reinitialize
```

### Directory Creation

When creating a new project directory:

```bash
chameleon init my-app
```

- Creates `my-app/` directory
- Sets up all files inside
- Reports error if directory already exists with `.chameleon.yml`

## After Initialization

### 1. Set Database Connection

```bash
export DATABASE_URL="postgresql://user:password@localhost/dbname"
```

Or edit `.chameleon.yml`:

```yaml
database:
  connection_string: "postgresql://localhost/mydb"
```

### 2. Edit Schema

Modify `schemas/example.cham` or create new schema files:

```bash
vim schemas/users.cham
```

### 3. Run First Migration

```bash
# Preview changes
chameleon migrate --dry-run

# Apply migration
chameleon migrate --apply
```

This will:
- Create the Schema Vault (.chameleon/vault/) on first use
- Register the schema as v001
- Run the generated SQL against the database

### 4. Set Mode Password (Recommended)

The vault is created by the first migration, so the password can only be set after it. New vaults start in `readonly`: from then on `migrate` and `introspect` are blocked until you run `chameleon config set mode=standard`.

## Version Control

Commit `.chameleon.yml`, `schemas/` and `README.md`. `init` already writes a `.chameleon/.gitignore` for `state/`, `journal/` and `backups/`. Add this to your project `.gitignore`:

```gitignore
.chameleon/vault/mode_auth.json
```

<Note>
  `vault/` is not ignored by default. Its `mode_auth.json` holds the hash of the mode password, so keep that file out of version control. Committing the rest of the vault (manifest, versions, hashes) is optional and gives you a shared audit trail.
</Note>

## Troubleshooting

### Permission Denied

Ensure you have write permissions in the target directory.

### Cannot Create Directory

Ensure parent directory exists:

```bash
mkdir -p path/to/project
chameleon init path/to/project/my-app
```
