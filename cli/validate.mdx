## Synopsis

```bash
chameleon validate [file]
```

Validate one schema file for syntax and semantic errors.

## Description

`validate` reads a single `.cham` file, parses it and type-checks it. It checks:

- **Syntax** - Entity, field and relation declarations
- **Primary keys** - Each entity has exactly one
- **Relations** - Target entities exist, foreign keys exist, and a has-many relation declares its `via` field
- **Duplicates** - Entity and field names are unique
- **Annotations** - `@vector` only on `vector(N)` fields; no backend annotations on primary or unique fields
- **Default values** - The default matches the field type
- **Circular dependencies** - Cycles between has-one and has-many relations

<Note>
  `validate` looks at one file. It does not merge several files, so a relation to an entity defined in another file is reported as unknown. To validate the merged schema from all the files in `schema.paths`, use `chameleon migrate --dry-run`.
</Note>

## Arguments

<ParamField path="file" type="string" optional>
  Path to the schema file.

  **Default:** `schema.cham` in the current directory if it exists. Otherwise, the schemas configured in `.chameleon.yml` (`schema.paths`, `./schemas` by default), merged as `migrate` does. `chameleon check` with no file and no stdin behaves the same way.
</ParamField>

## Flags

<ParamField path="-v, --verbose" type="boolean" default="false">
  After a successful validation, print the list of checks that were performed.
</ParamField>

## Examples

### Valid schema

```bash
chameleon validate schemas/example.cham
```

```
ℹ Validating schemas/example.cham...
✓ Schema is valid
```

With `--verbose`, a list of the checks performed follows.

### Errors

The message text comes from the Rust core. Parse errors include the line and column; type-check errors name the entity and field involved.

#### Syntax error

```chameleon
entity User {
    id: uuid primary
    email: string unique,
}
```

```bash
chameleon validate schemas/invalid.cham
```

```
ℹ Validating schemas/invalid.cham...
✗ Validation failed

Parse error at line 3, column 5: Unexpected token: Token(4, "email"), expected one of: ",", "@cache", ...
```

The list of expected tokens depends on the position of the error. A missing comma at the end of a field is a common cause.

#### Missing primary key

```chameleon
entity Post {
    title: string,
    content: string,
}
```

```
Entity 'Post' has no primary key
```

#### Unknown entity in a relation

```chameleon
entity Post {
    id: uuid primary,
    author: UnknownEntity,
}
```

```
Entity 'Post' references unknown entity 'UnknownEntity' in relation 'author'
```

#### Has-many without `via`

```chameleon
entity User {
    id: uuid primary,
    posts: [Post],
}
```

A has-many relation must declare the field that holds the foreign key:

```chameleon
posts: [Post] via author_id,
```

### File not found

```bash
chameleon validate missing.cham
```

```
schema file not found: missing.cham
```

## Exit codes

- `0` - The schema is valid
- Non-zero - Validation failed or the file was not found

## Integration with migrate

`chameleon migrate` loads and merges all the schema files from `schema.paths` and validates the result before it generates any SQL. If validation fails, the migration is aborted.

```bash
chameleon migrate --dry-run
```

## Best practices

### Validate before committing

```bash
# .git/hooks/pre-commit
#!/bin/bash
for file in schemas/*.cham; do
  chameleon validate "$file" || exit 1
done
```

Remember that each file is validated on its own: if entities reference each other across files, run `chameleon migrate --dry-run` instead.

### CI

```yaml
# .github/workflows/validate.yml
name: Validate Schema
on: [push, pull_request]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install ChameleonDB
        run: |
          curl -sSL https://chameleondb.dev/install -o install.sh
          # Review install.sh before running it. It does not verify checksums.
          sh install.sh
      - name: Validate schema
        run: chameleon validate schemas/example.cham
```

## Troubleshooting

### Validation passes but the migration fails

`validate` checks the schema, not its compatibility with your database. Use `chameleon migrate --dry-run` to see the generated SQL, and test it against a disposable database.
