# Installation

ChameleonDB is built from a Rust core and a Go CLI. Prebuilt archives are published on the [releases page](https://github.com/chameleon-db/chameleondb/releases) for Linux (amd64), macOS (universal) and Windows (amd64). On other platforms, build from source.

## Prerequisites

- **PostgreSQL**. Integration tests run against PostgreSQL 16; other versions are not yet verified.
- **Go 1.25.6 or newer**, to use the Go library or to build from source.
- **Rust (stable toolchain), a C compiler and `make`**, only to build from source.

## Quick install

<Tabs>
  <Tab title="Linux / macOS">
    ### Install script

    ```bash
    curl -sSL https://chameleondb.dev/install | sh
    ```

    The script:
    - Detects your platform and architecture
    - Downloads the latest release archive from GitHub
    - Installs the `chameleon` binary to `/usr/local/bin`, the native library to `/usr/local/lib` and the C header to `/usr/local/include`

    It uses `sudo` to write to those directories. To install elsewhere, set `CHAMELEON_INSTALL_DIR` and `CHAMELEON_LIB_DIR` before running it.

    <Warning>
      The script does not verify checksums. Read it before running it (`curl -sSL https://chameleondb.dev/install`), or use the manual or source installation below.
    </Warning>

    ### Verify

    ```bash
    chameleon version
    ```
  </Tab>

  <Tab title="Windows">
    ### Download

    <Steps>
      <Step title="Download">
        Download `chameleon-windows-amd64.tar.gz` from the [releases page](https://github.com/chameleon-db/chameleondb/releases).
      </Step>

      <Step title="Extract">
        Extract it with 7-Zip, or from a terminal with `tar -xzf chameleon-windows-amd64.tar.gz`.

        The archive contains `chameleon.exe` and `chameleon.dll` (plus `chameleon.h` and `chameleon.pc`).

        <Warning>
          `chameleon.exe` and `chameleon.dll` must stay in the same directory.
        </Warning>
      </Step>

      <Step title="Move to a folder">
        Create a folder, for example `C:\chameleon\`, and move the files there.
      </Step>

      <Step title="Add to PATH">
        1. Open **System Settings**, then **Environment Variables**
        2. Under **System variables**, select `Path` and click **Edit**
        3. Add `C:\chameleon\` (or your chosen path)
        4. Click **OK**

        <Note>
          Close and reopen your terminal for the change to take effect.
        </Note>
      </Step>

      <Step title="Verify">
        ```powershell
        chameleon version
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Manual installation

<AccordionGroup>
  <Accordion title="Linux (manual)">
    Download `chameleon-linux-amd64.tar.gz` from the [releases page](https://github.com/chameleon-db/chameleondb/releases). There is no prebuilt arm64 archive for Linux; build from source on that architecture.

    ```bash
    tar -xzf chameleon-linux-amd64.tar.gz
    sudo cp chameleon /usr/local/bin/
    sudo cp libchameleon.so* /usr/local/lib/
    sudo cp chameleon.h /usr/local/include/
    sudo ldconfig
    chameleon version
    ```

    <Note>
      Without sudo, install the binary to `~/bin` and the library to a directory you control, then add both to your `PATH` and `LD_LIBRARY_PATH`.
    </Note>
  </Accordion>

  <Accordion title="macOS (manual)">
    Download `chameleon-macos-universal.tar.gz` from the [releases page](https://github.com/chameleon-db/chameleondb/releases). It runs on Intel and Apple Silicon.

    ```bash
    tar -xzf chameleon-macos-universal.tar.gz
    sudo cp chameleon /usr/local/bin/
    sudo cp libchameleon*.dylib /usr/local/lib/
    sudo cp chameleon.h /usr/local/include/
    ```

    macOS may block the binary on first run. Remove the quarantine attribute from the files you downloaded:

    ```bash
    xattr -d com.apple.quarantine /usr/local/bin/chameleon
    ```

    ```bash
    chameleon version
    ```
  </Accordion>
</AccordionGroup>

## Build from source

<Steps>
  <Step title="Install prerequisites">
    - **Rust (stable)**: [https://rustup.rs](https://rustup.rs)
    - **Go 1.25.6 or newer**: [https://go.dev/dl](https://go.dev/dl)
    - **Git**, **make** and a **C compiler**
  </Step>

  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/chameleon-db/chameleondb.git
    cd chameleondb
    ```
  </Step>

  <Step title="Build">
    `make build` builds the Rust core first and then the Go CLI:

    ```bash
    cd chameleon
    make build
    ```

    This creates `chameleon/bin/chameleon`, linked to the library in `chameleon-core/target/release/`.
  </Step>

  <Step title="Install (optional)">
    ```bash
    sudo make install
    ```

    Or copy the binary and the library yourself:

    <CodeGroup>
    ```bash Linux
    sudo cp bin/chameleon /usr/local/bin/
    sudo cp ../chameleon-core/target/release/libchameleon.so /usr/local/lib/
    sudo cp ../chameleon-core/include/chameleon.h /usr/local/include/
    sudo ldconfig
    ```

    ```bash macOS
    sudo cp bin/chameleon /usr/local/bin/
    sudo cp ../chameleon-core/target/release/libchameleon.dylib /usr/local/lib/
    sudo cp ../chameleon-core/include/chameleon.h /usr/local/include/
    ```
    </CodeGroup>
  </Step>

  <Step title="Verify">
    ```bash
    chameleon version
    ```
  </Step>
</Steps>

## Using ChameleonDB as a Go SDK

The Go library is a supporting component and calls the Rust core through cgo, so the native library must be available when you build your application.

### Install the package

```bash
go get github.com/chameleon-db/chameleondb/chameleon@latest
```

You can pin a release, for example `@v1.1.0-alpha`.

### Requirements

- **Linux**: `libchameleon.so` in `/usr/local/lib` (or set `CGO_LDFLAGS`)
- **macOS**: `libchameleon.dylib` in `/usr/local/lib`
- **Windows**: `chameleon.dll` in the same directory as your `.exe`
- **Header**: `chameleon.h` in `/usr/local/include`

Install the library from a release archive (see manual installation) or build it yourself:

```bash
cd chameleon-core
cargo build --release

# Install the library (Linux)
sudo cp target/release/libchameleon.so /usr/local/lib/
sudo cp include/chameleon.h /usr/local/include/
sudo ldconfig
```

### Custom library location

If you install the library in a non-standard location:

```bash
CGO_LDFLAGS="-L/path/to/lib -Wl,-rpath,/path/to/lib -lchameleon" \
CGO_CFLAGS="-I/path/to/include" \
go build ./...
```

<Note>
  The release archives include a `chameleon.pc` file for `pkg-config`. This installation path is a known source of friction and is being re-evaluated.
</Note>

## Platform notes

<AccordionGroup>
  <Accordion title="Linux">
    ### Shared library location

    `libchameleon.so` must be in a directory that the dynamic linker searches:
    - `/usr/local/lib` (recommended)
    - `/usr/lib`
    - A custom path (requires `LD_LIBRARY_PATH` or an `ldconfig` configuration)

    After installing to `/usr/local/lib`:

    ```bash
    sudo ldconfig
    ```

    ### Verify the library

    ```bash
    ldd $(which chameleon)
    # Should show libchameleon.so => /usr/local/lib/libchameleon.so
    ```
  </Accordion>

  <Accordion title="macOS">
    ### Gatekeeper

    macOS may block binaries that are not signed or notarized. If you see a security warning:

    ```bash
    xattr -d com.apple.quarantine /usr/local/bin/chameleon
    ```

    ### Library location

    `libchameleon.dylib` should be in:
    - `/usr/local/lib` (recommended)
    - A custom path (requires `DYLD_LIBRARY_PATH`)

    ### Verify the library

    ```bash
    otool -L $(which chameleon)
    # Should show libchameleon.dylib
    ```
  </Accordion>

  <Accordion title="Windows">
    ### DLL location

    `chameleon.dll` must be:
    - In the same directory as `chameleon.exe`, or
    - In a directory listed in your `PATH`

    ### Verify the installation

    ```powershell
    Get-Command chameleon
    # Should show: C:\chameleon\chameleon.exe
    ```
  </Accordion>
</AccordionGroup>

## Docker

There is no official Docker image and no maintained Dockerfile. You can build ChameleonDB inside a container by following the "Build from source" steps; make sure the image has Go 1.25.6 or newer, a stable Rust toolchain, a C compiler and `make`, and that the runtime image contains `libchameleon.so`.

## Troubleshooting

<AccordionGroup>
  <Accordion title="command not found: chameleon">
    The binary is not in your `PATH`.

    **Solution:**
    - Check where it is installed: `which chameleon`
    - Add the directory to `PATH`: `export PATH="$PATH:/usr/local/bin"`
    - Or copy the binary there: `sudo cp chameleon /usr/local/bin/`
  </Accordion>

  <Accordion title="Install script fails to download (404)">
    The script could not find a release archive for your platform and architecture.

    **Solution:**
    - Check the available archives on the [releases page](https://github.com/chameleon-db/chameleondb/releases)
    - Follow the manual installation for your platform, or build from source
  </Accordion>

  <Accordion title="error while loading shared libraries: libchameleon.so">
    The shared library is not found.

    **Solution (Linux):**
    ```bash
    sudo cp libchameleon.so* /usr/local/lib/
    sudo ldconfig
    ```

    **Solution (macOS):**
    ```bash
    sudo cp libchameleon*.dylib /usr/local/lib/
    ```
  </Accordion>

  <Accordion title="cannot execute binary file">
    You downloaded the wrong architecture.

    **Solution:**
    - Check your architecture: `uname -m`
    - Download the matching archive, or build from source
  </Accordion>

  <Accordion title="Windows: The system cannot find the file specified">
    `chameleon.dll` is not in the same directory as `chameleon.exe`.

    **Solution:**
    - Keep both files together
    - Or add the DLL directory to your `PATH`
  </Accordion>
</AccordionGroup>
