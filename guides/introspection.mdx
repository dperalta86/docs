---
title: Database Introspection
description: Generate a draft .cham schema from an existing PostgreSQL database
---

`chameleon introspect` reads the tables of an existing PostgreSQL database and writes a draft `.cham` schema. It is useful to:

- Start from an existing database
- Compare what is in the database with your schema
- Get a baseline to edit by hand

<Note>
  Only PostgreSQL is supported.
</Note>

## Syntax

```bash
chameleon introspect <database-url> [--output <file>] [--force]
```

| Parameter | Short | Description | Default |
|-----------|-------|-------------|---------|
| `<database-url>` | - | Connection string (required) | - |
| `--output` | `-o` | Output file name; `.cham` is added if missing and the file is written under `schemas/` | `schema.cham` |
| `--force` | `-f` | Overwrite without asking, and without a backup | `false` |

The full command reference is in [`chameleon introspect`](/cli/introspect).

## Connection strings

```bash
# Direct URL
chameleon introspect "postgresql://user:pass@localhost:5432/mydb"

# Environment variable
export DATABASE_URL="postgresql://user:pass@localhost:5432/mydb"
chameleon introspect $DATABASE_URL
chameleon introspect '${DATABASE_URL}'
chameleon introspect env:DATABASE_URL
```

If the variable is unset or empty the command fails with `environment variable DATABASE_URL is not set or empty`.

## Workflow

<Steps>
  <Step title="Set the connection string">
    ```bash
    export DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
    ```
  </Step>

  <Step title="Check the integrity mode">
    Introspection is blocked in `readonly` mode **once a Schema Vault exists**. In a project with no vault yet (before the first `migrate`) the check is skipped with a warning.

    ```bash
    chameleon config get mode
    chameleon config auth set-password      # first time only
    chameleon config set mode=standard
    ```

    See [Managing Integrity Modes](/guides/mode-management).
  </Step>

  <Step title="Run it">
    ```bash
    chameleon introspect $DATABASE_URL -o introspected.cham
    ```

    ```
    ℹ Introspecting database...
    ✓ Database detected
    ℹ Scanning tables...
    ✓ Found 3 table(s)
    ℹ Generating schema...
    ✓ Schema written to schemas/introspected.cham
    ```
  </Step>

  <Step title="Review the generated schema">
    ```chameleon
    entity User {
        id: uuid primary,
        email: string unique,
        name: string,
        created_at: timestamp,
    }

    entity Post {
        id: uuid primary,
        title: string,
        content: string,
        author_id: uuid,
    }
    ```

    Table names become PascalCase entity names (`users` becomes `User`, `user_posts` becomes `UserPost`).
  </Step>

  <Step title="Validate and complete it">
    ```bash
    chameleon validate schemas/introspected.cham
    ```

    Then add what the generator does not produce (see below).
  </Step>
</Steps>

## What it produces, and what it does not

Produced: one entity per table, its columns with mapped types, `primary` and `unique`.

Not produced, so you add it by hand:

- **Relations.** Foreign keys are left as comments for you to review. Write the relations yourself:

  ```chameleon
  entity User {
      id: uuid primary,
      posts: [Post] via author_id,
  }

  entity Post {
      id: uuid primary,
      author_id: uuid,
      author: User,
  }
  ```

- **Defaults.** `DEFAULT NOW()` and the like are not copied.
- **Nullability.** Review which fields should be `nullable`.
- **Indexes, views, triggers and other constraints.**

### Type mapping

| PostgreSQL | ChameleonDB |
|------------|-------------|
| `uuid` | `uuid` |
| `text`, `varchar`, `character varying` | `string` |
| `integer`, `bigint`, `smallint` | `int` |
| `numeric`, `decimal` | `decimal` |
| `real`, `double precision` | `float` |
| `boolean` | `bool` |
| `timestamp`, `timestamp with time zone`, `date` | `timestamp` |
| anything else (`json`, `jsonb`, arrays, enums, ...) | `string` |

<Warning>
  Unmapped types silently become `string`. Review every field that is not a plain scalar.
</Warning>

## Integrity mode

| Mode | `introspect` |
|------|--------------|
| `readonly` (default after the first migration) | Blocked |
| `standard`, `privileged`, `emergency` | Allowed |

Moving out of `readonly` needs the mode password. Moving back does not.

## Overwrite protection

Without `--force`, if the output file already exists:

- **It is the default schema from `chameleon init`:** you are asked `Overwrite? (yes/no)`.
- **It has your own entities:** you choose `1` back up (`<file>.backup`) and overwrite, `2` enter a different file name, or `3` cancel.
- **The output path is a directory:** the command fails with `output path is a directory`.

`--force` skips these prompts and writes the file without a backup.

## Examples

### Keep the introspected schema separate

```bash
chameleon introspect $DATABASE_URL -o introspected.cham
diff schemas/schema.cham schemas/introspected.cham
```

### Dated baseline

```bash
chameleon introspect $DATABASE_URL -o baseline-$(date +%Y%m%d).cham
```

### Production

Use a read-only database role for the connection. Introspection only reads catalog metadata and never modifies the database, but a read-only role makes that a property of the connection and not of the tool.

## After introspecting

1. Validate each file with `chameleon validate <file>`.
2. Add relations, defaults and nullability.
3. Rename entities if you want different names.
4. Preview with `chameleon migrate --dry-run` and read the SQL.

<Warning>
  Do not run `chameleon migrate --apply` against the database you just introspected unless you have checked the preview. `migrate` is create-only: it creates tables that are missing and leaves existing ones as they are, but the script it prints is built from your schema and not from the database, so differences between the two are not reported. See [`chameleon migrate`](/cli/migrate).
</Warning>

## Common errors

| Message | What to do |
|---------|------------|
| `readonly mode: introspect is blocked` | Set a password and `chameleon config set mode=standard` |
| `environment variable DATABASE_URL is not set or empty` | Export it |
| `output path is a directory` | Pass a file name with `-o` |
| `failed to detect database` | Check the URL and that the server is reachable; only PostgreSQL is supported |
| `introspection failed` | Check that the user can read the tables |
